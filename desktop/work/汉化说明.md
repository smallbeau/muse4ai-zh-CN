# Muse4AI 本地简体中文汉化说明

> 适用于本机 `E:\Project\muse4ai\desktop`（版本 2.0.0-beta.34）。
> 这是**本地修改**，非官方中文版；上游仓库只有 `vi`（越南语，源语言）和 `en`（英语）两种界面语言。

## 一、原理

这个项目的所有 UI 文案在源码里以**越南语**写成，并直接作为查表键；
`src/shared/i18n/catalog/*.ts` 是「越南语 → 英文」的映射表。运行时按当前语言查表：
- `vi` → 直接显示源码里的越南语；
- `en` → 查 `CATALOG`，显示英文译文。

汉化采用**覆盖英文槽位**的办法：新增一个中文映射层，把它追加到 `CATALOG` 合并链的**最后一位**，
于是 `en` 这个语言槽显示的就是中文。语言 id 仍然是 `en`（没新增 `zh`），因此
`ipc.ts` 的 `z.enum(["vi","en"])`、更新器 `installerArgs(lang)`、数字/日期格式化、
以及已保存的 `settings.language = "en"` 全都不用改，改动面最小、随时可还原。

## 二、改动的文件

| 文件 | 改动 |
| --- | --- |
| `src/shared/i18n/catalog/zh.ts` | **新增**。越南语键 → 简体中文。由 `work/merge.mjs` 生成，只收录通过校验的条目。 |
| `src/shared/i18n/catalog/index.ts` | 加 `import zh from "./zh";`，并把它追加到 `Object.assign(..., updates, zh)` 末尾。 |
| `src/shared/i18n/index.ts` | `LOCALES` 里 `en` 的显示名 `English` → `中文`（id 仍是 `en`）。 |
| `src/renderer/styles.css` | 字体栈补上 `Microsoft YaHei` / `PingFang SC` / `Noto Sans CJK SC`，避免中文回退到宋体。 |

其余 5 个英文 catalog 文件**完全没动**。

## 三、如何切回英文 / 还原

- 临时：左下角语言切换保持「中文 / Tiếng Việt」两档；选 `Tiếng Việt` 是越南语，没有中文↔英文的切换（英文槽已被中文占用）。
- 完全还原英文（3 步）：
  1. 删除 `src/shared/i18n/catalog/index.ts` 里的 `import zh from "./zh";`；
  2. 把该文件的 `Object.assign(..., updates, zh)` 末尾的 `, zh` 删掉；
  3. `src/shared/i18n/index.ts` 把 `"中文"` 改回 `"English"`。
  然后 `npm run build` 并重启应用。`zh.ts` 与 `work/` 目录留着或删掉都不影响运行。

## 四、重新构建 / 重新生成译文

```bash
cd E:\Project\muse4ai\desktop
node work/merge.mjs            # 由 work/out/batch-*.json 重新生成 zh.ts
npm run typecheck && npm run build
```

`work/` 下的辅助文件：
- `prepare.mjs` —— 从 5 个英文 catalog 解析出 1835 条，切成 8 批 `batches/batch-01..08.json`；
- `TRANSLATE_RULES.md` —— 术语表与占位符规则；
- `out/batch-*.json` —— 各批中文译文（`[{i, zh}, ...]`）；
- `merge.mjs` —— 校验并合并；**校验不通过或缺失的键不写入 `zh.ts`，运行时自动回退英文**，绝不会显示越南语或空白；
- `merge-report.json` —— 覆盖率与被拒明细。

### 本次实测结果（2026-11-09）

- 8 批译文全部落盘，共 1835 条；`node work/merge.mjs` → **accepted 1829，回退英文 6，覆盖率 99.7%**。
- 6 条回退项全是纯占位符/纯符号（i=605、607、1011、1029、1120、1352），中英形态相同，无影响。
- `npx vitest run test/i18n-catalog.test.ts` → 5 项全过；`npm run typecheck && npm run build` → 通过，
  产物 `dist/renderer/assets/index-9QCJTdVM.js`（1,205.33 kB）。
- 完整 `npx vitest run` → 14 failed / 827 passed / 3 skipped；失败项均为断言写死英文文案的测试（见下第 6 条）。
- 重启应用后截图确认：Studio 首页「今天想创作什么？」、示例卡片、左侧导航「队列 / 批量 / 素材库 / 账户 / 设置 / 指南」、
  设置页「语言 / 素材库 / 外观 / 启动」等均已中文化，Microsoft YaHei 渲染正常无乱码。

## 五、已知边界（不是 bug）

1. **未覆盖的条目仍是英文**。`merge.mjs` 对译文做严格校验：占位符集合必须与越南语键一致、
   不得含 `|`、不得含越南语带调字母、必须含至少一个汉字。不合规就跳过 → 显示英文。
2. **纯占位符 / 纯符号条目**（如 `×{i}`、`{width}×{height}{value} · {bytes}`）没有自然语言，
   英文与中文形态相同，回退英文无影响。
3. **Guide / Agent Skill 文档**是独立的静态内容（`content/`、`agent-kit/`），不在 `CATALOG` 内，仍是英文。
4. **数字、日期、默认头像名、更新说明**按 `locale === "en"` 走英文分支，仍是英文格式。
5. **折叠侧栏的语言小按钮**显示 `EN` 徽标（它是语言 id 的大写，不是文案）；
   展开侧栏后显示的是完整标签「中文 / Tiếng Việt」。
6. 项目自带测试里有若干断言写死了英文界面文案，汉化后这些断言会失败
   （`npm test` 约 14 项失败：`i18n.test.ts`、`i18n-api.test.ts`、`guide.test.ts`、`oauth.test.ts`，
   另 `main-modules.test.ts` 的 zip 用例因本机没有 `python3` 而失败）。
   这些是**预期结果**，不是功能回归；`typecheck` 与 `build` 均通过，
   `i18n-catalog.test.ts`（占位符一致性校验）5 项全过。
